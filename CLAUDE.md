# Project Context

This app is the **backend admin tool** for a web catalog being built for The Honickman Companies. It is used internally by the team to manage product data, images, and catalog settings. Once the backend is sufficiently built out, it will be connected to a customer-facing front-end catalog (designed separately in another Figma Make project) accessible via the Honickman website.

# Deployment

## How deployment works
Changes are made in Figma Make. When the user says to deploy, push the code to GitHub. Vercel is connected to the GitHub repo and auto-deploys on every push to `main`.

**Never tell the user to click "Publish" in Figma Make — that is not part of this workflow.**

## GitHub repository
- Repo: `hahnhenry-prog/honickman-catalog-admin`
- Branch: `main`
- Remote name in local git: `github`

## Deploy steps
1. Build: `pnpm run build`
2. Push to GitHub: `git push github main`

If the remote hasn't been added yet:
```bash
git remote add github https://<GITHUB_TOKEN>@github.com/hahnhenry-prog/honickman-catalog-admin.git
```

## GitHub token
- Created manually by the user in GitHub → account Settings → Developer Settings → Personal access tokens
- Token is stored in `.env` as `GITHUB_TOKEN`
- Token expires (90 days as of last creation). If push fails with auth error, ask the user to generate a new one at GitHub and update `.env`
- Use the token in the remote URL: `https://<token>@github.com/...`

## Git LFS warning
The repo has a `.gitattributes` that previously tracked images via LFS. **Do not re-enable LFS** for images — it caused repeated push failures due to GitHub LFS infrastructure errors. Images belong in S3, not in git. The `.gitattributes` has been updated to remove image LFS tracking.

Do not commit product images or spreadsheets to `src/imports/`. Those are scratch files and belong in S3 only.

# Infrastructure

## AWS S3
- Bucket: `honickman-catalog-images`
- Region: `us-east-1`
- Key structure:
  - Original image: `products/full/{productId}.{ext}`
  - WebP compressed: `products/web/{productId}.webp`
  - Brand logos original: `brands/full/{brandId}.{ext}`
  - Brand logos web: `brands/web/{brandId}.webp`
- Images are uploaded directly from the browser using pre-signed PUT URLs
- WebP conversion (max 1200px, 85% quality) happens client-side via the Canvas API
